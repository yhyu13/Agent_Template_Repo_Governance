# Testing — 验证分级

「完成」必须有证据。证据分四级，改动越依赖真实世界，要求的级别越高。

| 级别 | 覆盖 | 例子 | 什么时候够 |
|---|---|---|---|
| **L1 静态** | 语法 / 格式 / 引用可达 | `bash -n`、`python -m py_compile`、`scripts/check-refs.py --all` | 纯文档、配置、脚本小改 |
| **L2 行为** | 逻辑分支 / 错误路径 | 单测、`pr-grade.sh --selftest`、构造反例实跑 | 改了判定逻辑、解析器、工具 |
| **L3 构建** | 整仓能装能跑 | `npm ci && npm run build`、CI 全绿 | 依赖、构建配置、CI 改动 |
| **L4 真实环境** | 真实时间 / 网络 / 设备 / 第三方账号 | 实调 API、真实 runner、真实浏览器 | 集成、部署、外部服务 |

**CI 绿不等于能构建**：CI 只在固定环境跑固定命令；L4 必须本地跑通。

## 每次改动的最低要求

| 改动 | 至少 |
|---|---|
| 文档 | L1 + `python scripts/check-refs.py --all` |
| 判定脚本 / 解析器 | L2 + 反例实跑（正常 / 越界 / 拼错 / 深度不同） |
| CI workflow | L3（本地跑一遍同名命令） |
| 外部集成 | L4 |

## 引用可达性是一等公民

```bash
python scripts/check-refs.py --all     # 全仓，退出码 0 才算过
python scripts/check-refs.py --pr <N>  # 只扫该 PR 触及的文件
```

它能查：路径不存在、相对路径越出仓根、md 锚点不存在、`file:line` 越界、列表字面量误判。
它**查不出**：引用指向的文件存在但内容对不上 → 那是 reviewer 的活（见 docs/REVIEW.md）。

**报告纪律**：写「N 处不可达引用」时，要能复现这个 N。
把忽略清单置空重跑一遍，看真实数字——否则「0 处」可能只是被 ignore 掩盖出来的。

## 反例自测（改判定逻辑时必做）

改解析器 / 判定器时，至少造这几个反例实跑：

| 反例 | 期望 |
|---|---|
| 相对路径少写/多写 `../` | 越出仓根 → 报 |
| 首段拼错（`docz/` vs `docs/`） | 报「疑似拼错」 |
| 裸文件名（`x.md`） | 同级目录 → 祖先链 → 仓内唯一同名；都没有则跳过 |
| 列表字面量 `['a', 'b']` | 不当路径 |
| 注释里的路径（`/* inlined: assets/x.css */`） | 不当活引用 |
| 同一文件在浅 / 深 checkout 下 | 结论一致 |

## 输出纪律

- 全量输出写进 git-ignored log，只看 tail（≤40 行）+ 立即捕获退出码。
- 失败数 > 0 时不得报完成；如实记录失败命令与退出码。
- 截图要能看出**状态**，不是能看出「有图」。
